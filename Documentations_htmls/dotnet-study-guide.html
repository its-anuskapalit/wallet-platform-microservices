01 .NET Framework & Core
The platform that runs your C# code — what it is, how it compiles, and where .NET Core fits in.
▶ What is .NET Platform? What is .NET Framework?
core

.NET Platform is Microsoft's developer ecosystem — a collection of tools, languages, and runtimes that let you build applications for Windows, web, mobile, cloud, and more.

.NET Framework is the original Windows-only implementation of that platform. It includes the CLR (runtime), BCL (base class library), and supports languages like C#, VB.NET, F#.

Quick mental model

  • Think of .NET Platform = the idea/specification
  • .NET Framework = Windows-only older implementation (v1.0–v4.8)
  • .NET Core / .NET 5+ = cross-platform modern implementation
  • Mono = community cross-platform implementation (used in Xamarin)

Architecture layers

┌────────────────────────────────────┐ │ Your App (C# / VB.NET / F#) │ ├────────────────────────────────────┤ │ BCL — Base Class Library │ ← String, List, File, etc. ├────────────────────────────────────┤ │ CLR — Common Language Runtime │ ← Manages execution, GC, JIT ├────────────────────────────────────┤ │ Operating System │ └────────────────────────────────────┘
Why it matters: Every feature you use in C# — from string to async/await — is provided either by the CLR or BCL. Knowing the layers helps you debug and make architecture decisions.
▶ CLR — Common Language Runtime
core

The CLR is the virtual machine that runs your .NET code. You write C# → compiler produces IL (Intermediate Language) → CLR's JIT compiler converts IL to native machine code at runtime.

What CLR manages for you

  • JIT Compilation — converts IL → native code per method, on first call
  • Garbage Collection — automatic memory management, no manual free()
  • Type Safety — prevents illegal memory access
  • Exception Handling — structured try/catch/finally across languages
  • Thread Management — managed threads, thread pool
  • Security — Code Access Security (CAS)

Compilation flow

C# Code (.cs) ↓ [C# Compiler — csc.exe / Roslyn] IL Code (.dll / .exe) ←— language-agnostic ↓ [CLR JIT Compiler — at runtime] Native Machine Code ↓ CPU Executes
CLS & CTS: CLS (Common Language Specification) = rules all .NET languages must follow. CTS (Common Type System) = defines how types work so C# and VB.NET can share objects.
▶ .NET Core — Overview, Versions, Composition, DI
core

.NET Core is the cross-platform, open-source rewrite of .NET Framework. It runs on Windows, Linux, and macOS. From .NET 5 onward the name became simply ".NET".

Key differences from .NET Framework

.NET Framework.NET Core / .NET 5+
Windows onlyCross-platform
Installed machine-wideCan be self-contained in app folder
System.Web (heavy)Middleware pipeline (lightweight)
No built-in DIBuilt-in Dependency Injection
Max v4.8, no new featuresActive development, .NET 8+ LTS

Dependency Injection (DI)

DI is a design pattern where objects receive their dependencies from outside rather than creating them. .NET Core has a built-in IoC container.

// Register in Program.cs builder.Services.AddScoped<IOrderService, OrderService>(); // Inject via constructor — no "new" keyword needed public class OrderController(IOrderService orderService) { private readonly IOrderService _svc = orderService; }

Service lifetimes

  • AddSingleton — one instance for the entire app lifetime
  • AddScoped — one instance per HTTP request
  • AddTransient — new instance every time it's requested
02 C# Language Basics
Types, variables, arrays, and the quirks you'll hit daily.
▶ Value Types vs Reference Types · Boxing & Unboxing
core

Value types store data directly in memory (stack). Reference types store a pointer to data on the heap.

Value TypesReference Types
int, float, double, bool, char, struct, enumclass, string, array, interface, delegate
Stored on StackStored on Heap, pointer on Stack
Copy on assignmentReference copy on assignment
No null (unless Nullable<T>)Can be null
int a = 5; int b = a; // b gets a COPY — changing b doesn't change a Person p1 = new Person { Name = "Anuska" }; Person p2 = p1; // p2 points to SAME object — changing p2.Name changes p1.Name!

Boxing & Unboxing

Boxing = wrapping a value type in an object (goes to heap). Unboxing = pulling it back out. Both are performance-heavy — avoid in hot paths.

int x = 42; object boxed = x; // Boxing — heap allocation happens here int unboxed = (int)boxed; // Unboxing — explicit cast required
⚠ Performance tip: Generics (List<int>) avoid boxing. Always prefer generics over non-generic collections like ArrayList when possible.
▶ Arrays — Single, Multi-dimensional, Jagged

Nullable Types

int? age = null; // int? = Nullable<int> if (age.HasValue) Console.WriteLine(age.Value); int result = age ?? 18; // Null-coalescing: use 18 if age is null

ref vs out

  • ref — variable must be initialized before passing; method can read AND write it
  • out — variable doesn't need initialization; method MUST assign it before returning
void Double(ref int x) => x *= 2; bool ok = int.TryParse("42", out int parsed); // out — parsed assigned inside

is vs as

▶ String vs StringBuilder · Parse vs TryParse vs Convert
core

string is immutable — every concatenation creates a new object. StringBuilder mutates a buffer in-place — use it in loops.

// BAD — creates 1000 string objects in memory string result = ""; for (int i = 0; i < 1000; i++) result += i; // GOOD — one buffer, one final ToString() var sb = new StringBuilder(); for (int i = 0; i < 1000; i++) sb.Append(i); string result = sb.ToString();

Convert.ToInt32(null)Returns 0 for nullWorking with DB nulls
03 OOP in C#
Object-Oriented Programming concepts — the backbone of all .NET code.
▶ Access Modifiers · Abstract · Sealed · Method Hiding
core

Access Modifiers

ModifierAccessible from
publicAnywhere

protected internalSame assembly OR derived class

Abstract vs Sealed

// Abstract — cannot instantiate, child must implement abstract members abstract class Shape { public abstract double Area(); // no body public virtual void Draw() { ... } // can override } // Sealed — cannot be inherited (opposite of abstract) sealed class FinalClass { }

Method Hiding (new keyword)

class Base { public void Show() => Console.WriteLine("Base"); } class Child : Base { public new void Show() => Console.WriteLine("Child"); // hides base } Base obj = new Child(); obj.Show(); // "Base" — hiding is NOT polymorphism // Use override (with virtual) for true polymorphism
Hiding vs Overriding: override + virtual = runtime polymorphism. new (hiding) = compile-time, based on declared type. Hiding is usually a design smell.
▶ Interfaces · Interface Inheritance · Properties in Interfaces
core

An interface defines a contract — what methods/properties a class must have, without saying how. A class can implement multiple interfaces (unlike inheritance — only one base class).

interface IAnimal { string Name { get; } // property in interface void MakeSound(); string Describe() => $"I am {Name}"; // default impl (C# 8+) } interface IPet : IAnimal { // interface inheritance string Owner { get; } } class Dog : IPet { public string Name => "Rex"; public string Owner => "Alice"; public void MakeSound() => Console.WriteLine("Woof!"); }
When to use interface vs abstract class? Interface = capability contract (IDisposable, IComparable). Abstract class = shared base behavior with partial implementation. Use interfaces for "can do", abstract class for "is a".
04 Advanced C# Features
Generics, extension methods, properties, indexers, and patterns that make C# expressive.
▶ Generics — Classes, Methods, Constraints
advanced

Generics let you write type-safe, reusable code without knowing the type at design time. No boxing overhead. Compiler enforces correctness.

// Generic class class Box<T> { public T Value { get; set; } } // Generic method T GetMax<T>(T a, T b) where T : IComparable<T> => a.CompareTo(b) > 0 ? a : b; // Constraints where T : class // must be reference type where T : struct // must be value type where T : new() // must have parameterless constructor where T : BaseClass // must inherit from BaseClass
▶ Extension Methods · Object Initializers · Anonymous Types · Partial Types
advanced

Extension Methods

Add methods to existing types without modifying them. Must be in a static class, first param is this TypeName.

public static class StringExtensions { public static bool IsEmail(this string s) => s.Contains('@') && s.Contains('.'); } // Usage: "hello@world.com".IsEmail(); // true — reads like a native method

Object Initializer

var p = new Person { Name = "Anuska", Age = 24 }; // no separate assignment lines

Anonymous Types

var anon = new { Name = "Alice", Score = 95 }; // compiler generates class Console.WriteLine(anon.Name); // but type has no name — often used in LINQ projections

Partial Types

Split a class definition across multiple files. Useful for generated code (designer files) + your hand-written code.

// File1.cs public partial class Order { public int Id { get; set; } } // File2.cs public partial class Order { public void Process() { } }
▶ Regular Expressions in C#
advanced

Regex lets you match, search, and replace patterns in strings. Use System.Text.RegularExpressions.Regex.

using System.Text.RegularExpressions; string email = "anuska@example.com"; bool isValid = Regex.IsMatch(email, @"^[\w.-]+@[\w.-]+\.\w{2,}$"); // Replace string cleaned = Regex.Replace("Hello World", @"\s+", " "); // Groups var match = Regex.Match("2024-05-03", @"(\d{4})-(\d{2})-(\d{2})"); string year = match.Groups[1].Value; // "2024"

Common patterns

  • \d — digit, \w — word char, \s — whitespace
  • + — one or more, * — zero or more, ? — optional
  • ^ — start, $ — end, [] — character class
  • () — capture group, | — OR
05 Exception Handling & Memory Management
How .NET handles errors and reclaims memory — critical for production code.
▶ Exception Handling — try/catch/finally · Custom Exceptions · Best Practices
core
try { int result = 10 / GetDivisor(); } catch (DivideByZeroException ex) { _logger.LogError(ex, "Division by zero"); throw; // rethrow — preserves original stack trace } catch (Exception ex) when (ex.Message.Contains("timeout")) { // exception filter throw new AppException("Service timeout", ex); // wrap with inner exception } finally { // ALWAYS runs — cleanup here (close connections etc.) }

Custom Exception

public class OrderNotFoundException : Exception { public int OrderId { get; } public OrderNotFoundException(int id) : base($"Order {id} not found") => OrderId = id; }

Best Practices

  • Never catch Exception and swallow it silently — always log
  • Use specific exception types — catch the narrowest applicable type
  • Use throw; not throw ex; to preserve stack trace
  • Validate inputs early (guard clauses) to avoid exceptions altogether
  • Wrap exceptions with context using inner exceptions
▶ Garbage Collection · Finalize vs Dispose
advanced

The GC automatically finds unreachable objects and frees their memory. It uses a generational algorithm: Gen 0 (short-lived) → Gen 1 → Gen 2 (long-lived).

GC Algorithm

  • Mark — trace all reachable objects from GC roots (stack, static fields)
  • Sweep — reclaim memory of unreachable objects
  • Compact — defragment heap (moves objects together)

Finalize vs Dispose

Finalize (~Destructor)Dispose (IDisposable)
Called by GC — unpredictable timingCalled explicitly by you or using block
Unmanaged resource cleanupAny resource cleanup
Do NOT access managed objects (may be collected)Can access managed objects
// Always use 'using' for IDisposable — auto-calls Dispose() using var conn = new SqlConnection(connStr); conn.Open(); // Dispose() called automatically when scope ends, even if exception thrown

07 Delegates, Events & LINQ
Function pointers done right, event-driven programming, and querying data like SQL in C#.
▶ Delegates · Multicast · Action · Func · Predicate
advanced

A delegate is a type-safe function pointer. It holds a reference to a method with a specific signature.

// Declare delegate int MathOp(int a, int b); // Assign and invoke MathOp add = (a, b) => a + b; Console.WriteLine(add(3, 4)); // 7 // Multicast — multiple methods on one delegate Action greet = () => Console.WriteLine("Hello"); greet += () => Console.WriteLine("Hi"); greet(); // prints both

Built-in generic delegates

  • Action<T> — takes params, returns void: Action<string> print = Console.WriteLine;
  • Func<T, TResult> — takes params, returns value: Func<int,int,int> add = (a,b) => a+b;
  • Predicate<T> — takes T, returns bool: Predicate<int> isEven = x => x%2==0;
▶ Events in C#
advanced

Events are a wrapper around delegates that enforce the publisher-subscriber pattern. Subscribers can only += or -= — they can't invoke the event directly.

class Button { public event EventHandler Clicked; // declare event public void Click() => Clicked?.Invoke(this, EventArgs.Empty); } var btn = new Button(); btn.Clicked += (s, e) => Console.WriteLine("Button clicked!"); btn.Click();
▶ LINQ — Query Syntax · Lambda · Operators
advanced

LINQ (Language Integrated Query) lets you query any IEnumerable<T> or IQueryable<T> using SQL-like syntax — in-memory collections, databases (via EF), XML, etc.

var students = new List<Student>(...); // Method syntax (most common) var topScorers = students .Where(s => s.Score > 80) .OrderByDescending(s => s.Score) .Select(s => new { s.Name, s.Score }) // projection .Take(5) .ToList(); // Query syntax (more readable for joins) var result = from s in students where s.Score > 80 orderby s.Score descending select s;

Key operators

  • Where — filter, Select — transform/project, SelectMany — flatten nested
  • GroupBy — group, Join/GroupJoin — join collections
  • Any/All — existential checks, Count/Sum/Avg/Min/Max — aggregates
  • FirstOrDefault/SingleOrDefault — retrieve elements safely
  • ToList/ToArray/ToDictionary — materialize (force evaluation)
Lazy evaluation: LINQ queries don't run until you iterate or call ToList(). This is called deferred execution. Be aware — calling ToList() inside a loop is a common performance mistake.

Thread vs Task

  • Task: uses thread pool, supports async/await, cancelation, continuations — prefer Task over Thread in modern code
▶ async / await · Task Parallel Library · Locks
advanced

async/await lets you write asynchronous code that looks synchronous. The method returns a Task but doesn't block the thread while waiting for I/O.

// Without async — BLOCKS the thread for 2 seconds string data = client.GetStringAsync(url).Result; // DEADLOCK RISK // WITH async — thread is free while waiting public async Task<string> GetDataAsync() { string data = await client.GetStringAsync(url); return data.ToUpper(); }

Parallel programming

// Parallel.For — run loop iterations in parallel Parallel.For(0, 100, i => ProcessItem(i)); // Parallel.ForEach Parallel.ForEach(items, item => Process(item)); // Task.WhenAll — run multiple tasks concurrently, await all var results = await Task.WhenAll(FetchA(), FetchB(), FetchC());

Locking — prevent race conditions

private readonly object _lock = new(); private int _counter = 0; void Increment() { lock (_lock) { _counter++; } // only one thread at a time }
⚠ Deadlock: Never lock on this or public objects. Never hold two locks simultaneously without consistent ordering.

▶ JOINs · Subqueries · GROUP BY · HAVING
database
-- INNER JOIN — only matching rows SELECT o.id, c.name FROM orders o INNER JOIN customers c ON o.customer_id = c.id; -- LEFT JOIN — all left rows + matched right (NULL if no match) SELECT c.name, o.id FROM customers c LEFT JOIN orders o ON c.id = o.customer_id; -- GROUP BY + HAVING (filter on aggregates) SELECT dept, COUNT(*) total, AVG(salary) avg_sal FROM employees GROUP BY dept HAVING AVG(salary) > 50000; -- WHERE filters rows, HAVING filters groups -- Correlated subquery SELECT name FROM employees e WHERE salary > (SELECT AVG(salary) FROM employees WHERE dept = e.dept);
▶ Normalization — 1NF, 2NF, 3NF, BCNF
database
  • 1NF — atomic values only, no repeating groups, primary key exists
  • 2NF — 1NF + no partial dependency (non-key columns depend on WHOLE primary key)
  • 3NF — 2NF + no transitive dependency (non-key columns depend only on PK, not other non-key columns)
  • BCNF — 3NF + every determinant is a candidate key (stricter 3NF)
Practical rule: Normalize to 3NF for OLTP. For OLAP/reporting (star schema), intentional denormalization is fine — query speed matters more than write efficiency.

advanced

17 Authentication & JWT
Securing your APIs — who you are (authentication) vs what you can do (authorization).
▶ JWT Structure · Auth Flow · Token Validation · Role/Policy Auth
advanced

A JWT (JSON Web Token) = Header.Payload.Signature — a self-contained, signed token the client sends on every request.

// Configure JWT in Program.cs builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme) .AddJwtBearer(o => { o.TokenValidationParameters = new TokenValidationParameters { ValidateIssuer = true, ValidateAudience = true, ValidateLifetime = true, ValidateIssuerSigningKey = true, IssuerSigningKey = new SymmetricSecurityKey( Encoding.UTF8.GetBytes(config["Jwt:Key"])) }; }); // Protect endpoint [Authorize] // any authenticated user [Authorize(Roles = "Admin")] // role-based [Authorize(Policy = "CanEdit")] // policy-based

Flow

  • User POSTs credentials → server validates → generates JWT → returns to client
  • Client stores JWT (localStorage or cookie) → sends in Authorization: Bearer {token} header
  • Server validates signature on every request — no session lookup needed

Page Object Model (POM)

Each page = one class. Locators and actions live in the class. Tests just call methods — no raw Selenium in test code. Makes tests maintainable.

public class LoginPage { private readonly IWebDriver _driver; private IWebElement UserField => _driver.FindElement(By.Id("user")); public void Login(string user, string pass) { UserField.SendKeys(user); _driver.FindElement(By.Id("pass")).SendKeys(pass); _driver.FindElement(By.Id("submit")).Click(); } } // NUnit test [TestFixture] public class LoginTests { [Test] public void ValidLogin_RedirectsToDashboard() { var page = new LoginPage(driver); page.Login("admin", "pass123"); Assert.That(driver.Url, Does.Contain("dashboard")); } }

📌 Core Angular Concepts (Must for Freshers)
🔹 1. What is Angular? How is it different from AngularJS?

Answer: Angular is a TypeScript-based open-source front-end framework developed by Google for building dynamic single-page applications (SPAs). It's a complete rewrite of AngularJS (v1.x).

  • AngularJS: Uses JavaScript, controllers & $scope, MVC pattern.
  • Angular (2+): Uses TypeScript, component-based architecture, better performance, mobile support, and CLI.
💡 Key improvements: Unidirectional data flow, Ahead-of-Time (AOT) compilation, RxJS for async tasks.
🔹 2. Explain the core building blocks of an Angular application.

Answer: Main building blocks: Modules, Components, Templates, Metadata, Data Binding, Directives, Services, Dependency Injection.

  • Modules (NgModules): Container for components, directives, pipes.
  • Components: Controls a part of the screen (HTML + logic).
  • Templates: HTML with Angular bindings.
  • Services: Reusable business logic/data across components.
// app.module.ts (root module)
@NgModule({
  declarations: [AppComponent, UserComponent],
  imports: [BrowserModule, FormsModule],
  providers: [UserService],
  bootstrap: [AppComponent]
})
export class AppModule { }
🔹 3. List important Angular component lifecycle hooks with examples.

Answer: Lifecycle hooks (ordered): ngOnChanges, ngOnInit, ngDoCheck, ngAfterContentInit, ngAfterContentChecked, ngAfterViewInit, ngAfterViewChecked, ngOnDestroy.

export class DemoComponent implements OnInit, OnDestroy {
  ngOnInit() {
    console.log('Component initialized - ideal for API calls');
  }
  ngOnDestroy() {
    console.log('Cleanup subscriptions to avoid memory leaks');
  }
}
📌 Most common: ngOnInit (initialization), ngOnDestroy (cleanup).
🔹 4. Explain all types of data binding in Angular with code.

Answer: Angular supports four types:

  • Interpolation: {{ value }} → one-way from component to DOM.
  • Property binding: [property]="expression"
  • Event binding: (event)="handler()"
  • Two-way binding: [(ngModel)]="property" (FormsModule required)
<!-- component.html -->
<h2>Hello {{ userName }}</h2>
<button [disabled]="isDisabled" (click)="saveData()">Save</button>
<input [(ngModel)]="userName" placeholder="Edit name" />
🔹 5. What are directives? Explain structural vs attribute directives with examples.

Answer: Directives are instructions to manipulate DOM. Types: Structural (change layout: *ngIf, *ngFor, *ngSwitch) and Attribute (change appearance/behavior: ngClass, ngStyle, custom).

<!-- Structural -->
<div *ngIf="isLoggedIn">Welcome back!</div>
<li *ngFor="let item of items">{{ item }}</li>

<!-- Attribute -->
<div [ngClass]="{'highlight': isActive}">Styled div</div>
<button [ngStyle]="{'background': color}">Click</button>
🔹 6. Explain services and dependency injection in Angular with code.

Answer: Services are singleton objects that encapsulate reusable logic (HTTP calls, shared data). Angular's DI system provides dependencies to components.

// data.service.ts
@Injectable({ providedIn: 'root' })
export class DataService {
  getProducts() { return ['Laptop', 'Mouse']; }
}

// product.component.ts
export class ProductComponent {
  constructor(private dataService: DataService) { }
  products = this.dataService.getProducts();
}
✅ Using providedIn: 'root' makes service a singleton across app.
🔹 7. What are Observables in Angular? How to handle HTTP requests?

Answer: Observables (RxJS) handle async operations like HTTP requests, events. Angular's HttpClient returns Observables. You subscribe to get data.

// user.service.ts
getUsers(): Observable<User[]> {
  return this.http.get<User[]>('https://api.example.com/users');
}

// component.ts
this.userService.getUsers().subscribe({
  next: (data) => this.users = data,
  error: (err) => console.error(err)
});
⚡ Can use async pipe in template to auto-subscribe/unsubscribe.
🔹 8. How does Angular routing work? Show a simple route configuration.

Answer: RouterModule enables navigation between views. Define routes, then use <router-outlet> to render components.

// app-routing.module.ts
const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'products', component: ProductsComponent },
  { path: 'detail/:id', component: ProductDetailComponent }
];
// navigation in template
<a routerLink="/products">Products</a>
<button routerLink="/detail/5">View 5</button>
<router-outlet></router-outlet>
🔹 9. What are pipes? Demonstrate built-in and custom pipe.

Answer: Pipes transform data in templates. Built-in: DatePipe, CurrencyPipe, UpperCasePipe. Custom pipes implement PipeTransform.

<p>Today: {{ today | date:'fullDate' }}</p>
<p>Price: {{ productPrice | currency:'INR' }}</p>

// Custom pipe to truncate text
@Pipe({ name: 'truncate' })
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit: number = 10): string {
    return value.length > limit ? value.substr(0, limit) + '...' : value;
  }
}
// usage: {{ longText | truncate:20 }}
🔹 10. Compare template-driven forms vs reactive forms with code.

Answer: Template-driven: uses ngModel, easier but less scalable. Reactive: uses FormGroup, FormControl, more testable & powerful.

<!-- Template-driven -->
<input [(ngModel)]="user.name" required #name="ngModel" />

// Reactive form
this.profileForm = new FormGroup({
  name: new FormControl('', [Validators.required]),
  email: new FormControl('', [Validators.email])
});
<form [formGroup]="profileForm">
  <input formControlName="name" />
</form>
🚀 Advanced & Interview Favorites
🔹 11. How does Angular's change detection work? What is OnPush strategy?

Answer: Angular checks component's bindings after each async event. Default = CheckAlways. OnPush strategy checks only when input references change or events fire inside component. Improves performance.

@Component({
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class ListComponent { ... }
🔹 12. What is lazy loading in Angular? Show route configuration.

Answer: Lazy loading loads feature modules on-demand, reducing initial bundle size.

const routes: Routes = [
  { path: 'admin', loadChildren: () => import('./admin/admin.module').then(m => m.AdminModule) }
];
✅ Improves startup performance, great for large enterprise apps.

🔹 14. Explain component communication using @Input and @Output with example.

Answer: Parent → Child using @Input(). Child → Parent using @Output() EventEmitter.

// child.component.ts
@Input() productName: string;
@Output() notify = new EventEmitter<string>();

sendToParent() { this.notify.emit('Item purchased'); }

// parent template
<app-child [productName]="'Laptop'" (notify)="onNotify($event)"></app-child>
🔹 15. What is ViewChild? Provide a practical scenario.

Answer: @ViewChild gives access to child component/directive/DOM element from component class.

<input #myInput type="text" />
@ViewChild('myInput') inputRef: ElementRef;
ngAfterViewInit() { this.inputRef.nativeElement.focus(); }
🔹 16. How to protect routes using AuthGuard?

Answer: Implement CanActivate interface in a guard service.

@Injectable({ providedIn: 'root' })
export class AuthGuard implements CanActivate {
  canActivate(): boolean { return this.auth.isLoggedIn; }
}
// routes: { path: 'dashboard', canActivate: [AuthGuard], component: DashboardComponent }
🔹 17. What is AOT (Ahead-of-Time) compilation vs JIT?

Answer: AOT compiles Angular templates at build time → smaller bundle, faster rendering, fewer errors. JIT compiles at runtime in browser. AOT is default in production builds.

🔹 18. What is async pipe and why is it useful?
<div *ngFor="let user of users$ | async">{{ user.name }}</div>

Automatically subscribes to Observable/Promise and unsubscribes on component destroy — prevents memory leaks.

🔹 19. What are standalone components? How are they different?

Answer: Standalone components don't require NgModule. They manage their own dependencies, simplifying app structure.

@Component({
  standalone: true,
  imports: [CommonModule, FormsModule],
  selector: 'app-profile',
  template: `<h2>Standalone!</h2>`
})
🔹 20. How does hierarchical dependency injection work in Angular?

Angular has injector tree. A component can have its own injector that falls back to parent. Provided services can be scoped at root, module, or component level.

@Component({ providers: [LocalService] }) // new instance for component + children

📌 Core MVC Concepts (must know for freshers)
🔹 1. What is MVC architecture? Explain each component with real-world analogy.

Answer: MVC (Model-View-Controller) is a design pattern that separates an application into three interconnected components. This separation improves modularity, scalability, and maintainability.

  • Model: Manages data, business logic, and rules. It notifies observers (View) about changes. Analogy: Chef in a restaurant (prepares food data)
  • View: Handles presentation & UI. Shows data to the user. Analogy: Waiter serving the food on a plate (visual representation)
  • Controller: Accepts input, processes requests, updates model, and selects view. Analogy: Restaurant cashier/receptionist who takes orders & coordinates.
💡 Modern frameworks: Spring MVC, Ruby on Rails, Django, ASP.NET Core all follow MVC pattern.
🔹 2. Show a simple MVC code example (Python/Java style) with explanation.

Answer: Below is a Python console-based MVC example for a Student Management System.

# ---------- MODEL ----------
class StudentModel:
    def __init__(self):
        self.students = []   # list of dicts

    def add_student(self, name, grade):
        student = {"id": len(self.students)+1, "name": name, "grade": grade}
        self.students.append(student)
        return student

    def get_all_students(self):
        return self.students

# ---------- VIEW ----------
class StudentView:
    @staticmethod
    def show_students(students):
        print("\n📋 Student List:")
        if not students:
            print("No records found.")
        for s in students:
            print(f"ID: {s['id']} | Name: {s['name']} | Grade: {s['grade']}")

    @staticmethod
    def show_message(msg):
        print(f"[INFO] {msg}")

# ---------- CONTROLLER ----------
class StudentController:
    def __init__(self, model, view):
        self.model = model
        self.view = view

    def add_new_student(self, name, grade):
        if not name or grade < 0:
            self.view.show_message("Invalid data!")
            return
        student = self.model.add_student(name, grade)
        self.view.show_message(f"Student '{name}' added with ID {student['id']}")

    def display_all(self):
        students = self.model.get_all_students()
        self.view.show_students(students)

# ---------- USAGE ----------
if __name__ == "__main__":
    model = StudentModel()
    view = StudentView()
    controller = StudentController(model, view)

    controller.add_new_student("Alice", 92)
    controller.add_new_student("Bob", 85)
    controller.display_all()
✅ Explanation: Model stores data, View handles output formatting, Controller coordinates actions. The View never talks directly to Model — only Controller mediates. This keeps code decoupled & testable.
🔹 3. What are the main advantages and disadvantages of MVC?

Advantages:

  • Separation of concerns → easier maintenance & testing.
  • Parallel development (designers work on View, developers on Model/Controller).
  • Reusability of Model and Controllers across different views.
  • Supports multiple views for same model (e.g., charts + tables).

Disadvantages:

  • Increased complexity for simple apps.
  • Steep learning curve for beginners.
  • Heavy navigation between layers may impact performance.
  • Requires strict discipline in larger projects.
🔹 4. Explain the request flow in a typical MVC web application (Spring MVC / ASP.NET).

Answer: The flow follows a specific cycle:

  1. User sends a request (e.g., clicks a button → URL).
  2. Controller receives the request (via Front Controller / Dispatcher Servlet).
  3. Controller processes input, interacts with Model (database/ business logic).
  4. Model updates data and returns result to Controller.
  5. Controller selects the appropriate View (JSP, Thymeleaf, React template).
  6. View renders the response (HTML/JSON) and sends back to client.
// Spring MVC pseudo flow:
@Controller
public class UserController {
    @Autowired UserService service;   // Model layer
    
    @GetMapping("/profile")
    public String showProfile(Model model) {
        User user = service.getCurrentUser();  // fetch from Model
        model.addAttribute("user", user);      // pass data to View
        return "profileView";                  // returns view name
    }
}
🔹 5. How is MVC different from MVP and MVVM? (Bonus for advanced freshers)

Answer: All are UI architectural patterns:

  • MVC: Controller handles user input, updates Model, View is passive (observes Model).
  • MVP (Model-View-Presenter): Presenter mediates between View & Model; View is completely passive, Presenter updates UI.
  • MVVM (Model-View-ViewModel): ViewModel exposes data/commands; View binds to ViewModel properties (used in WPF, Angular).
In MVC, the View can sometimes access Model directly (in classic MVC). In modern web MVC (Spring), View is usually dumb and receives data from Controller.
🔹 6. What should be placed in the Model? Does it include database access?

Answer: Model contains business entities, data access logic, validation rules, and domain logic. It should NOT contain UI code. In many frameworks, the Model includes DAO (Data Access Objects) or Repository classes. The Model is the heart of the application state.

// Model class in Java (POJO) + service
@Entity
public class Product {
    @Id private Long id;
    private String name;
    private BigDecimal price;
    // business method: apply discount
    public void applyDiscount(double percent) {
        this.price = price.multiply(BigDecimal.valueOf(1 - percent/100));
    }
}
// Repository (also part of Model layer)
public interface ProductRepository extends JpaRepository<Product, Long> { }
🔹 7. Can View contain logic? What kind of logic is allowed?

Answer: View should only contain presentation logic — formatting dates, looping through lists, conditional display. Business logic or data manipulation belongs in Model/Controller. Thick views are an anti-pattern. Example: In JSP/Thymeleaf, you can use if-else for rendering but not database calls.

<!-- Thymeleaf view example (allowed logic) -->
<div th:each="product : ${products}">
    <p th:text="${product.name}"></p>
    <p th:if="${product.price < 100}">🔥 Sale!</p>
</div>
🔹 8. What are the typical responsibilities of a Controller?

Answer: Controller is the "traffic director":

  • Receive and validate HTTP/input parameters.
  • Call appropriate Model methods (services).
  • Select the correct View for response.
  • Redirect or forward requests.
  • Handle user sessions and authentication (sometimes delegated).
Controllers should be thin — avoid embedding complex business logic. Delegate to services (Model layer).
🔹 9. How would you handle form submission in MVC? Write a code snippet (Spring MVC / pseudo).

Answer: Controller receives form data, validates, updates model, then redirects or shows a success view.

// Controller (Spring MVC)
@PostMapping("/register")
public String registerUser(@Valid @ModelAttribute UserDto userDto, 
                           BindingResult result, Model model) {
    if(result.hasErrors()) {
        return "registrationForm";   // return to same view with errors
    }
    userService.registerNewUser(userDto);  // delegate to model
    model.addAttribute("message", "Registration successful!");
    return "loginView";
}

Workflow: View (HTML form) → POST → Controller → Model updates → redirect/renders view.

🔹 10. Is MVC stateless? How to manage session data?

Answer: Web MVC (HTTP based) is naturally stateless. However, session state can be maintained using HttpSession (server-side) or cookies. Controllers can inject session attributes. Best practice: avoid storing large objects in session; use database or cache when needed.

@Controller
public class CartController {
    @GetMapping("/cart")
    public String viewCart(@SessionAttribute("shoppingCart") Cart cart, Model model) {
        model.addAttribute("cart", cart);
        return "cartView";
    }
}
🔹 11. What is Front Controller in MVC frameworks? Provide example.

Answer: Front Controller is a design pattern where a single controller (like DispatcherServlet in Spring, or a central router) handles all incoming requests, delegates actions, and centralizes common tasks (security, logging, navigation).

Most web MVC frameworks implement Front Controller to provide a centralized entry point, improving consistency and reducing duplication.
🔹 12. How does MVC help with unit testing and integration testing?

Answer: Because MVC separates concerns, you can test each component independently:

  • Model: Unit test business logic without UI.
  • Controller: Mock Model & View to test request mappings, validation, and flow.
  • View: Test rendering logic (if needed).
// Example JUnit test for Controller (Spring MockMvc)
mockMvc.perform(post("/register")
       .param("email", "test@example.com"))
       .andExpect(status().isOk())
       .andExpect(view().name("successView"));

🔹 14. Can a View directly communicate with another View? If not, why?

Answer: No. In MVC, Views should never directly communicate with each other. Any interaction or navigation should go through the Controller. This maintains loose coupling and prevents spaghetti code. The Controller decides which View to render next based on the application state.

If View A needs to pass data to View B, it should notify Controller, and Controller updates Model/triggers View B.
🔹 15. How would you implement a dashboard showing same data as chart + table using MVC?

Answer: Use same Model instance but different View templates. Controller fetches the model (sales data) and passes it to two separate views: one renders a chart, the other a table. The Model stays unchanged.

@Controller
public class DashboardController {
    @GetMapping("/sales/table")
    public String tableView(Model model) {
        model.addAttribute("salesData", salesService.getSales());
        return "salesTable";
    }
    
    @GetMapping("/sales/chart")
    public String chartView(Model model) {
        model.addAttribute("salesData", salesService.getSales());
        return "salesChart";
    }
}

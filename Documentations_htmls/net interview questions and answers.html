⚡ OOP Core Concepts: Overloading vs Overriding

Fresher’s deep dive — compile-time polymorphism vs runtime polymorphism with real Java-style examples
🔁 Compile-time Polymorphism

📌 Function Overloading

Same name, different parameters — within the same class

Definition: Function overloading allows a class to have multiple methods with the same name but different parameter lists (type, number, or order). The compiler decides which method to call at compile time.

// Java example: Calculator class demonstrates overloading
class Calculator {
    // add() with two int parameters
    public int add(int a, int b) {
        return a + b;
    }
    
    // overloaded: three int parameters
    public int add(int a, int b, int c) {
        return a + b + c;
    }
    
    // overloaded: two double parameters
    public double add(double a, double b) {
        return a + b;
    }
    
    // overloaded: different order (String concatenation demo)
    public String add(String text, int number) {
        return text + number;
    }
}

public class MainOverload {
    public static void main(String[] args) {
        Calculator calc = new Calculator();
        System.out.println("add(5,10) = " + calc.add(5,10));          // calls int,int
        System.out.println("add(2,3,4) = " + calc.add(2,3,4));        // calls int,int,int
        System.out.println("add(2.5,3.7) = " + calc.add(2.5,3.7));    // calls double,double
        System.out.println("add(\"Score: \", 99) = " + calc.add("Score: ", 99));
    }
}
🧠 Explanation: The add method appears 4 times with different signatures. The compiler matches the method call based on argument count & type. Overloading improves readability & provides flexibility. It is NOT affected by return type — return type alone cannot distinguish overloads. Overloading works across different access modifiers. This is static/compile-time polymorphism.
🔄 Runtime Polymorphism

🎯 Function Overriding

Re-defining a parent class method in child class — same signature

Definition: When a subclass provides a specific implementation of a method already defined in its superclass, it's called overriding. The method signature (name + parameters) must remain identical. Overriding enables runtime polymorphism (dynamic method dispatch).

// Java example: Animal hierarchy
class Animal {
    public void sound() {
        System.out.println("Animal makes a generic sound");
    }
    
    public void eat() {
        System.out.println("Animal eats food");
    }
}

class Dog extends Animal {
    @Override   // good practice: annotation ensures overriding
    public void sound() {
        System.out.println("Dog barks: Woof Woof!");
    }
    
    // optional: adding specialized behavior
    public void wagTail() {
        System.out.println("Dog wags tail happily");
    }
}

class Cat extends Animal {
    @Override
    public void sound() {
        System.out.println("Cat meows: Meow Meow");
    }
}

public class MainOverride {
    public static void main(String[] args) {
        Animal myAnimal = new Animal();
        Animal myDog = new Dog();      // upcasting
        Animal myCat = new Cat();
        
        myAnimal.sound();   // Animal version
        myDog.sound();      // Dog's overridden version -> runtime decision
        myCat.sound();      // Cat's version
        
        // myDog.wagTail();  // not allowed (reference type Animal)
        // to access specific methods, downcast if needed
        if(myDog instanceof Dog) {
            ((Dog) myDog).wagTail();
        }
    }
}
🧠 Explanation: The sound() method is overridden in Dog and Cat. At runtime, the JVM invokes the actual object's method, not the reference type's method. Overriding requires same method name, parameters, and return type (covariant return types allowed). You cannot override private or final methods. @Override annotation helps catch errors. This is core to achieving polymorphism & dynamic behavior.

🧠📘 OOP Interview Questions (Fresher friendly) with Code Examples

Most commonly asked OOP concepts in tech interviews — inheritance, encapsulation, abstraction, polymorphism, and more.

🔹 1. What are the four pillars of OOP? Explain with real-life analogy.

Answer: The four pillars are Encapsulation, Inheritance, Polymorphism, and Abstraction.

  • Encapsulation: Binding data & methods together, hiding internal state (e.g., a capsule).
  • Inheritance: Child class acquires properties of parent (e.g., Son inherits traits from Father).
  • Polymorphism: One entity many forms (e.g., a person behaves as student, employee).
  • Abstraction: Hiding implementation details & showing only essential features (e.g., driving a car without knowing engine mechanism).
// Encapsulation example
class BankAccount {
    private double balance;   // hidden data
    public void deposit(double amt) { if(amt>0) balance+=amt; }
    public double getBalance() { return balance; }
}
🔹 2. Explain constructor overloading with code example.

Answer: Multiple constructors in a class with different parameter lists — used to initialize objects in various ways.

class Employee {
    String name;
    int id;
    // no-arg constructor
    Employee() {
        name = "Unknown";
        id = 0;
    }
    // parameterized constructor
    Employee(String name, int id) {
        this.name = name;
        this.id = id;
    }
    // overloaded with only name
    Employee(String name) {
        this(name, -1);
    }
    public void display() {
        System.out.println(name + " , ID: " + id);
    }
}

Constructor overloading offers flexibility to create objects with default or custom values.

🔹 3. Can we override static methods in Java? Why?

Answer: No, static methods cannot be overridden because they belong to the class, not the instance. Method overriding is based on runtime object type, while static methods are resolved at compile time. However, you can "hide" a static method in subclass.

class Parent {
    static void show() { System.out.println("Parent static"); }
}
class Child extends Parent {
    static void show() { System.out.println("Child static"); }  // hiding, not overriding
}
// Parent p = new Child(); p.show(); → calls Parent's version
🔹 4. What is the difference between abstract class and interface?

Answer: Abstract class can have both abstract & concrete methods, instance variables, constructors. Interface (prior to Java 8) had only abstract methods; from Java 8+, default & static methods allowed. A class can extend only one abstract class but implement multiple interfaces.

abstract class Vehicle {
    abstract void start();
    void fuel() { System.out.println("Filling fuel"); }
}
interface Electric {
    void chargeBattery();
}
class Tesla extends Vehicle implements Electric {
    void start() { System.out.println("Tesla silent start"); }
    public void chargeBattery() { System.out.println("Charging..."); }
}
🔹 5. What is the "diamond problem" in multiple inheritance? How does Java resolve it?

Answer: Diamond problem occurs when a class inherits from two classes that have a method with same signature, causing ambiguity. Java doesn't support multiple inheritance with classes, but supports multiple inheritance via interfaces. Since Java 8, if two interfaces provide default methods with same signature, the implementing class must override the method or specify which super-interface to use.

interface A { default void show() { System.out.println("A"); } }
interface B { default void show() { System.out.println("B"); } }
class C implements A, B {
    // must override to resolve conflict
    public void show() { A.super.show(); }   // choose A's version
}
🔹 6. Demonstrate method overriding with 'super' keyword usage.

Answer: 'super' is used to invoke parent class method from overridden method in child, allowing reuse of parent logic.

class Vehicle {
    void run() { System.out.println("Vehicle is moving"); }
}
class Bike extends Vehicle {
    @Override
    void run() {
        super.run();   // calls parent method
        System.out.println("Bike runs safely with 2 wheels");
    }
}
// new Bike().run(); output both statements.
🔹 7. What is the Liskov Substitution Principle (LSP) in SOLID?

Answer: LSP states that objects of a superclass should be replaceable with objects of a subclass without affecting correctness. Overriding methods should not strengthen preconditions or weaken postconditions. Example: If Rectangle is parent and Square child, changing width independently breaks LSP.

🔹 8. Can we overload or override the main() method in Java?

Answer: Yes, we can overload main() but JVM always calls the standard public static void main(String[] args) as the entry point. Overloaded main methods act like normal methods. Overriding main() is not possible because it's static.

public class Test {
    public static void main(String[] args) { 
        System.out.println("Standard main");
        main(10);
    }
    public static void main(int x) { 
        System.out.println("Overloaded main: " + x);
    }
}
🔹 9. What is the difference between compile-time polymorphism and runtime polymorphism?

Answer: Compile-time polymorphism (method overloading) resolves method calls at compile time based on reference type. Runtime polymorphism (method overriding) decides method execution at runtime based on actual object type. Overloading is faster but overriding provides flexibility.

// Overloading (compile time): 
MathOperation.add(2,3); // resolved early
// Overriding (runtime):
Animal a = new Dog(); a.sound(); // which sound()? determined at runtime.
🔹 10. Explain encapsulation with a real-world banking code example.

Answer: Encapsulation hides data (balance) and exposes controlled access via public methods, protecting integrity.

class Account {
    private double balance;
    private String accountNumber;
    
    public Account(String accNo, double initBal) {
        this.accountNumber = accNo;
        if(initBal >= 0) this.balance = initBal;
    }
    public void withdraw(double amount) {
        if(amount > 0 && amount <= balance) {
            balance -= amount;
            System.out.println("Withdrawn: " + amount);
        } else {
            System.out.println("Insufficient balance");
        }
    }
    public double getBalance() { return balance; }
}
// external code can't modify balance directly, enforces rules
🔹 11. Can we have a private method overridden in Java?

Answer: No. Private methods are not visible in subclasses, so they cannot be overridden. However, a subclass can declare a method with same name — it's a new method, not an override.

🔹 12. What is covariant return type in method overriding?

Answer: From Java 5+, an overriding method can return a subclass (more specific type) of the return type declared in parent method. This is called covariant return type.

class X { }
class Y extends X { }
class Parent { X getObject() { return new X(); } }
class Child extends Parent { 
    @Override 
    Y getObject() { return new Y(); }  // allowed: Y is subclass of X
}
